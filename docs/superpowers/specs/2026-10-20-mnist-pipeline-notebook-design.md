# Наглядный ноутбук полного пайплайна MNIST

## Назначение

Создать самодостаточный учебный Jupyter-ноутбук на русском языке, который показывает весь существующий пайплайн проекта на MNIST как последовательную воронку экспериментов. На каждом этапе сравниваются все доступные варианты, один вариант фиксируется, и с ним выполняется следующий этап.

## Сценарий

1. Загрузить воспроизводимые подвыборки `train`, `val` и `test` MNIST через существующий загрузчик и показать примеры изображений.
2. Сравнить все разложения из `DECOMPOSITIONS`: `dct`, `block_dct`, `dft`, `wavelet`. Для `block_dct` использовать размер блока 7, потому что изображение MNIST имеет размер 28×28. Показать коэффициенты, распределения, точность полного обратного преобразования и качество реконструкции при сохранении 5%, 10%, 25% и 50% крупнейших по модулю коэффициентов. Выбрать разложение по минимальному validation MSE при 25% коэффициентов и передать его на следующий этап.
3. Для выбранного разложения сравнить все порядки из `ORDERINGS`: `zigzag`, `dyadic`, `radial`, `block`. Для порядка `block` использовать `block_size=7`. Показать карты первых позиций и качество реконструкции из префиксов длиной 5%, 10%, 25% и 50%. Выбрать порядок по минимальному validation MSE при 25% коэффициентов и передать его на следующий этап.
4. Для выбранного разложения и порядка сравнить восемь сочетаний нормализации: `none`/`signed_log`, `minmax`/`standard`, общий режим/`per_position`. Для `signed_log` использовать `log_scale=255.0`, совпадающий со значением по умолчанию в `Tokenizer`. Поскольку нормализация сама по себе обратима, сравнивать её после одинаковой общей uniform-квантизации в 64 бина (`per_position=False`). Выбрать сочетание по минимальному validation MSE и передать его на следующий этап.
5. С выбранными предыдущими этапами сравнить uniform-квантизацию с 16, 32, 64, 128 и 256 бинами в общем режиме и `per_position`. Показать MSE, PSNR и размер словаря. Выбрать конфигурацию по минимальному validation MSE.
6. Собрать итоговый `Tokenizer`, обучая параметры только на train; показать токены, реконструкции на test, ошибки и итоговую таблицу выбранной конфигурации.

## Визуальный стиль

- Русские Markdown-пояснения перед каждым экспериментом.
- Компактные сетки изображений, тепловые карты коэффициентов, гистограммы и линейные графики MSE/PSNR.
- На каждом этапе отдельный заметный блок «Выбранный вариант».
- Итоговая галерея «оригинал → реконструкция → абсолютная ошибка».

## Ограничения и принятые решения

- Использовать только MNIST и существующие модули `src`, не дублируя реализацию пайплайна.
- Использовать небольшие лимиты выборок по умолчанию, чтобы ноутбук выполнялся на CPU за разумное время; значения вынести в одну конфигурационную ячейку.
- Выбор конфигураций делать на validation, а test использовать только для финальной оценки.
- Должен выполняться сверху вниз из корня репозитория и автоматически скачивать MNIST при отсутствии локальных данных.
- Не добавлять новые методы обработки в библиотеку: задача демонстрирует уже реализованные варианты.

## Критерии готовности

- Ноутбук является валидным `.ipynb`, все кодовые ячейки компилируются и выполняются по порядку.
- Присутствуют все четыре разложения, четыре порядка, восемь вариантов нормализации и десять вариантов квантизации.
- Все выборы между этапами явно показаны и используются дальше.
- Финальные токены имеют целый тип и допустимый диапазон; реконструкции имеют форму MNIST `(N, 1, 28, 28)` и конечные метрики.
