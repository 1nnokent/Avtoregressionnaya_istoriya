# Техническая спецификация и руководство по использованию

Проект: «Авторегрессионная генерация изображений».  
Ветка: `codex/unified-experiments`.  
Дата сверки с кодом: 20 октября 2026 года.  
Документ описывает существующую реализацию и порядок подготовки будущих экспериментов.

## 1. Назначение и границы работ

Проект объединяет загрузку данных, преобразование изображений в токены, авторегрессионную модель, обучение, генерацию и оценку качества в один конфигурируемый конвейер.

Пользователь должен иметь возможность выбрать уже поддерживаемые данные, преобразования, параметры модели и метрики в YAML-файле и передать этот файл одному скрипту запуска.

На текущем этапе задача — обеспечить возможность обучения и описать работу с системой. Запуск обучения, подбор гиперпараметров и получение новых экспериментальных результатов не являются частью подготовки этого документа. Команды `train` ниже приведены как инструкции для будущего запуска.

Основные сценарии:

1. Подготовить окружение.
2. Создать конфиг эксперимента на основе общего конфига.
3. Проверить конфиг без загрузки данных и обучения.
4. В дальнейшем запустить полный эксперимент отдельной командой.
5. Просмотреть логи и сохранённые результаты.
6. Повторно оценить сохранённую модель без изменения её весов.

## 2. Архитектура и состав проекта

Основной поток данных:

```text
Изображения train/val/test
    → разложение DCT / block DCT / DFT / wavelet
    → упорядочивание коэффициентов
    → выбор длины последовательности
    → нормализация и квантование
    → последовательности целочисленных токенов
    → causal Transformer
    → сгенерированные токены
    → обратное преобразование в изображения
    → метрики и артефакты
```

| Файл или каталог | Ответственность |
| --- | --- |
| `run_experiment.py` | Основной CLI: `validate`, `train`, `evaluate` |
| `configs/base.yaml` | Общие настройки всех экспериментов |
| `configs/*.yaml` | Конфиги отдельных экспериментов |
| `src/config.py` | Чтение YAML, наследование, переопределения и создание модели |
| `src/datasets_loader.py` | Загрузка наборов и разбиение train/val |
| `src/decomposition.py` | Прямые и обратные разложения |
| `src/ordering.py` | Порядок обхода коэффициентов |
| `src/normalization.py` | Normalizer из data/baseline: signed log, minmax/standard |
| `src/tokenizer.py` | Tokenizer из data/baseline и адаптер ImageTokenizer для общего запуска |
| `src/model.py` | Transformer с causal attention и RoPE |
| `src/train.py` | Обучение, validation, сохранение и загрузка checkpoint |
| `src/generation.py` | Генерация изображений батчами |
| `src/evaluation.py` | Связь генераций, энкодеров и метрик |
| `src/metrics/encoders.py` | Энкодеры `mnist`, `pixels`, `inception`, `clip` |
| `src/metrics/scores.py` | Fréchet, classifier score и kNN precision/recall |
| `src/logging_utils.py` | JSONL и TensorBoard |
| `src/artifacts.py` | Сохранение изображений и графика loss |
| `src/experiment.py` | Полный жизненный цикл эксперимента |
| `scripts/setup.ps1` | Настройка окружения Windows |
| `scripts/export_run.py` | Копирование небольших артефактов завершённого запуска в отчёт |
| `tests/` | Проверки конфигов, преобразований и конвейера |
| `data/` | Локальные данные и кэш; исключены из Git |
| `runs/` | Полные результаты запусков; исключены из Git |

`src/pipeline.py` сохраняет прежний DCT API для совместимости. Основной runner использует `ImageTokenizer` — адаптер над `Tokenizer`, `Normalizer` и `Quantizer` из актуальной ветки данных. Адаптер добавляет усечение, сериализацию и чтение старого формата состояния. В `Quantizer` также сохранена поддержка квантильного квантования общего запуска.

## 3. Окружение

### 3.1. Принятый способ запуска

Основной вариант — локальный запуск под Python 3.12. Реализован выбор CPU, CUDA и MPS. Отдельных конфигов окружения или ноутбуков для Colab/Kaggle в текущем проекте нет.

Все команды в документе выполняются из корня репозитория. Для текущего компьютера:

```powershell
Set-Location 'D:\Projects\PythonProjects\Avtoregressionnaya_istoriya'
```

Если `.venv` уже подготовлено, повторная установка не нужна. Проверка существующего окружения:

```powershell
.venv/Scripts/python.exe --version
uv pip check --python .venv/Scripts/python.exe
```

### 3.2. Первая установка в Windows

Требуются установленный Python 3.12 и команда `uv`. Setup-скрипт создаёт окружение и устанавливает зависимости. Напечатанная им команда обучения является подсказкой: скрипт её не выполняет.

CPU:

```powershell
./scripts/setup.ps1
```

Вариант с CUDA-колёсами PyTorch:

```powershell
./scripts/setup.ps1 -Device cu128
```

Для второго варианта нужны совместимые NVIDIA GPU и драйвер. Сам проект не устанавливает драйвер и не проверяет совместимость драйвера при валидации YAML.

Активация виртуального окружения не обязательна, если вызывать `.venv/Scripts/python.exe` явно.

### 3.3. Файлы зависимостей

| Файл | Назначение |

| `requirements.txt` | Основные зависимости с фиксированными версиями |


## 4. Основные команды

### 4.1. Проверить конфиг без обучения

```powershell
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_baseline.yaml
```

Команда читает YAML, разрешает наследование и CLI-переопределения, проверяет основные настройки и печатает итоговый конфиг. Она не скачивает датасеты, не создаёт модель и не выполняет обучение или генерацию.

Это проверка конфигурации, а не полная проверка возможности запуска: наличие файлов данных, доступность CUDA, импорт пользовательской модели и совместимость некоторых аргументов преобразований проверяются позднее при их использовании.

### 4.2. Полный эксперимент — только для будущего запуска

Следующая команда действительно запускает обучение:

```powershell
.venv/Scripts/python.exe run_experiment.py train --config configs/mnist_baseline.yaml
```

Она выполняет весь цикл: загрузку данных, подбор параметров токенизатора, обучение модели, выбор checkpoint, генерацию изображений, расчёт метрик и сохранение артефактов.

При `metrics.encoders: [mnist]` в этом цикле дополнительно обучается вспомогательный классификатор для метрик. Его обучение тоже включено в `train`.

`configs/smoke.yaml` уменьшает объём работы, но команда `train --config configs/smoke.yaml` также обновляет веса модели. Для проверки без обучения используется именно `validate`.

### 4.3. Имя конкретного запуска

```powershell
.venv/Scripts/python.exe run_experiment.py train --config configs/mnist_baseline.yaml --run-id experiment_01
```

Будущий результат окажется в `runs/mnist_dct64_baseline/experiment_01/`. Если каталог уже существует, запуск завершится ошибкой. Без `--run-id` идентификатор создаётся автоматически: UTC-время и случайный суффикс.

### 4.4. Повторная оценка сохранённого запуска

Пример после появления соответствующего каталога:

```powershell
.venv/Scripts/python.exe run_experiment.py evaluate --run-dir runs/mnist_dct64_baseline/experiment_01 --device cpu
```

`evaluate` загружает сохранённый конфиг, токенизатор и `best.pt`. Для MNIST-метрик требуется также сохранённый `mnist_encoder.pt`. Веса не обучаются. Перед оценкой проверяется соответствие загруженных данных сохранённым SHA256.

Оценка повторно выполняет генерацию, пересчитывает метрики и обновляет `generated.npz`, изображения и `evaluation.json` в каталоге запуска; записи в логах дополняются. Это не команда только для чтения результатов. Файл `summary.json` остаётся отчётом исходного полного запуска.

В `evaluate` доступны `--run-dir` и необязательный `--device cpu/cuda/mps`. Флаги `--config` и `--set` для этой команды не реализованы.

Совместимые старые точки входа: `train.py --config ...` и `python -m src.evalute --run-dir ...`. Для новых инструкций следует использовать `run_experiment.py`.

## 5. Как устроены конфиги

### 5.1. Наследование

Общие значения находятся в `configs/base.yaml`. Конфиг эксперимента содержит только отличия:

```yaml
extends: base.yaml
experiment:
  name: my_experiment
training:
  learning_rate: 0.0003
  max_steps: 1000
```

`extends` разрешается относительно файла, в котором он указан. Если новый конфиг лежит в `configs/variants/`, путь к общему конфигу будет `../base.yaml`.

Вложенные словари объединяются: изменение `training.learning_rate` не удаляет `training.batch_size`. Списки заменяются целиком: `metrics.encoders: [pixels]` заменит `[mnist]`.

Циклическое наследование и неизвестные ключи основных разделов отклоняются. Словари `model.params`, `decomposition_params` и `ordering_params` допускают аргументы соответствующих классов и функций.

Общий конфиг тоже применяется как основа при загрузке файла без `extends`. Для ясности и переносимости примеров следует указывать наследование явно.

### 5.2. Переопределения через CLI

Можно проверить другой набор значений, не изменяя YAML:

```powershell
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_baseline.yaml --set experiment.name=mnist_variant --set training.batch_size=32 --set training.max_steps=1000
```

Для будущего запуска используются те же аргументы с подкомандой `train`.

Значения справа от `=` разбираются как YAML: числа, `true/false`, `null` и списки. Пример:

```powershell
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_baseline.yaml --set 'metrics.encoders=[pixels]' --set 'metrics.scores=[frechet,precision,recall]' --set logging.tensorboard=false
```

`--set` меняет только существующий ключ. Новые параметры пользовательской архитектуры или новые поля `decomposition_params` задаются в YAML. Для сложных списков, путей с пробелами и нескольких параметров преобразования YAML удобнее CLI.

### 5.3. Пути

| Настройка | Относительно чего разрешается |
| --- | --- |
| Аргумент `--config` | Текущий рабочий каталог терминала |
| `extends` | Каталог текущего YAML-файла |
| `data.root` | Корень репозитория; абсолютный путь также допустим |
| `experiment.output_dir` | Корень репозитория; абсолютный путь также допустим |
| Аргумент `--run-dir` | Текущий рабочий каталог терминала |

Для путей Windows внутри YAML удобно использовать `/`: `D:/datasets/images.npz`. После запуска в сохранённом конфиге `data.root` будет абсолютным.

## 6. Справочник настроек

Значения по умолчанию ниже взяты из `configs/base.yaml`. Конфиг эксперимента и CLI могут их изменять.

### 6.1. `experiment` и `runtime`

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `experiment.name` | `experiment` | Имя группы запусков; латинские буквы, цифры, `_`, `-` |
| `experiment.seed` | `42` | Seed разбиения, инициализации и загрузчиков |
| `experiment.output_dir` | `runs` | Корневой каталог результатов |
| `runtime.device` | `auto` | `auto`, `cpu`, `cuda` или `mps` |
| `runtime.num_threads` | `4` | Число CPU-потоков PyTorch |
| `runtime.num_workers` | `0` | Workers загрузчика токенов; целое неотрицательное |

`auto` выбирает CUDA, затем MPS, иначе CPU. Принудительное недоступное устройство вызывает ошибку при настройке runtime. Увеличение `num_workers` не превращает загрузку исходных изображений в потоковую: изображения и токены уже подготовлены в RAM.

### 6.2. `data`

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `ds_name` | `mnist` | `mnist`, `cifar10`, `celeba`, `imagenet`, `npz` |
| `root` | `data` | Каталог наборов или путь к NPZ-файлу |
| `gray` | `true` | Перевод изображений в grayscale |
| `size` | `28` | Итоговая сторона квадратного изображения |
| `val_fraction` | `0.1` | Доля validation, выделяемая из train |
| `train_limit` | `4096` | Максимальное число train-изображений; `null` — все |
| `val_limit` | `512` | Лимит validation; `null` — все |
| `test_limit` | `512` | Лимит test; `null` — все |
| `download` | `true` | Разрешение загрузки MNIST/CIFAR10 через torchvision |

Для MNIST, CIFAR10, ImageNet и NPZ train/val выделяются одним и тем же воспроизводимым разбиением официального или заданного train. Лимиты применяются после разбиения. CelebA использует готовые train/valid/test из разметки набора.

`gray: false` сохраняет RGB для цветных наборов. MNIST остаётся одноканальным. На вход токенизатора поступает `float32[N,C,H,W]` в диапазоне `[0,1]`.

### 6.3. `tokenizer`

| Поле | По умолчанию | Допустимые значения или смысл |
| --- | --- | --- |
| `decomposition` | `dct` | `dct`, `block_dct`, `dft`, `wavelet` |
| `decomposition_params` | `{}` | Аргументы разложения |
| `ordering` | `zigzag` | `zigzag`, `radial`, `dyadic`, `block` |
| `ordering_params` | `{}` | Аргументы обхода, например `block_size` |
| `max_tokens` | `64` | Число сохраняемых токенов; `null` — полная последовательность |
| `normalization.transform` | `signed_log` | `signed_log` или `none` |
| `normalization.log_scale` | `255.0` | Положительный масштаб signed log |
| `normalization.scaling` | `minmax` | `minmax` или `standard` после signed log/none |
| `normalization.per_position` | `false` | Отдельные параметры нормализации для каждой позиции |
| `quantization.method` | `uniform` | `uniform` или `quantile` |
| `quantization.num_bins` | `64` | Целый размер словаря, не менее 2 |
| `quantization.per_position` | `true` | Отдельные параметры квантования для каждой позиции |

Полная длина последовательности равна `C × H × W`. Для MNIST 28×28 это 784, для RGB 32×32 — 3072. `max_tokens` не может превышать полную длину.

Коэффициенты каждого канала упорядочиваются отдельно, затем каналы соединяются последовательно. Усечение применяется к общей последовательности. Для RGB значение меньше `H×W` сохранит только часть первого канала; готовый CIFAR10-конфиг поэтому использует `max_tokens: null`.

При декодировании отброшенные коэффициенты заполняются нулями в пространстве разложения. Усечение и квантование приводят к потерям; encode/decode не гарантирует точное восстановление пикселей.

Параметры квантования подбираются только на train. Validation/test используют те же параметры; значения за границами диапазона квантования ограничиваются допустимыми токенами.

Для блочного DCT размер блока должен делить обе стороны изображения. Например, для 28×28:

```yaml
tokenizer:
  decomposition: block_dct
  decomposition_params: {block_size: 7}
  ordering: block
  ordering_params: {block_size: 7}
  max_tokens: null
```

Для wavelet доступны параметры `wavelet` и `level`. Пример для 28×28:

```yaml
tokenizer:
  decomposition: wavelet
  decomposition_params: {wavelet: haar, level: 2}
  ordering: dyadic
```

Разложение должно сохранять форму изображения. Неподходящая комбинация размера, wavelet и уровня может быть отклонена при токенизации, даже если YAML прошёл `validate`.

### 6.4. `model`

По умолчанию:

```yaml
model:
  class_path: src.model.ImageTokenTransformer
  config_class: src.model.ModelConfig
  params:
    d_model: 64
    n_heads: 4
    n_layers: 2
    d_ff: 128
    dropout: 0.0
```

| Параметр | Назначение |
| --- | --- |
| `class_path` | Python-путь к классу модели |
| `config_class` | Python-путь к классу конфигурации модели |
| `d_model` | Размерность скрытых представлений |
| `n_heads` | Число attention-голов |
| `n_layers` | Число Transformer-блоков |
| `d_ff` | Размерность промежуточного слоя FFN |
| `dropout` | Вероятность dropout, от 0 включительно до 1 исключительно |

Встроенный Transformer требует положительных размерностей, делимости `d_model` на `n_heads` и чётной размерности каждой головы для RoPE. Эти проверки выполняются конструктором модели, а не командой `validate`.

`vocab_size` и `max_seq_len` всегда задаются runner автоматически из токенизатора. Указанные вручную значения этих двух параметров будут заменены.

### 6.5. `training`

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `batch_size` | `64` | Число изображений/последовательностей в батче |
| `epochs` | `10` | Максимальное число проходов по train |
| `max_steps` | `400` | Предел обновлений весов; `null` — без отдельного предела |
| `learning_rate` | `0.001` | Скорость обучения AdamW |
| `weight_decay` | `0.01` | Weight decay AdamW |
| `grad_clip` | `1.0` | Максимальная норма градиента |
| `log_interval` | `20` | Интервал логирования train NLL в шагах |
| `eval_interval` | `100` | Интервал validation в шагах |

Цикл завершается по первому достигнутому ограничению: `epochs` или `max_steps`. Без отбрасывания последнего батча верхняя граница шагов равна `epochs × ceil(N_train / batch_size)`, дополнительно ограниченная `max_steps`, если он задан.

Перед первым обновлением вычисляется initial validation. `best.pt` обновляется при снижении validation NLL; последняя итерация также оценивается. Если улучшения не было, лучшим может остаться checkpoint шага 0. `latest.pt` сохраняется в конце каждой начатой эпохи и при завершении цикла.

Learning-rate scheduler, early stopping, gradient accumulation и mixed precision через конфиг сейчас не реализованы.

### 6.6. `generation`

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `num_samples` | `256` | Число сгенерированных изображений |
| `batch_size` | `64` | Батч генерации |
| `temperature` | `0.8` | Положительная температура распределения токенов |
| `top_k` | `null` | Ограничение сэмплирования top-k; `null` — без ограничения |

Генерация безусловная: метки классов не передаются Transformer. Токены создаются последовательно; KV-кэш не реализован. Для генерации используется `experiment.seed + 1`.

### 6.7. `metrics` и `logging`

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `metrics.encoders` | `[mnist]` | Список энкодеров изображений |
| `metrics.scores` | `[frechet, classifier_score, precision, recall]` | Список оценок |
| `metrics.batch_size` | `64` | Батч извлечения признаков |
| `metrics.knn_k` | `3` | Число соседей для precision/recall |
| `metrics.classifier_epochs` | `5` | Эпохи вспомогательного MNIST-классификатора |
| `metrics.clip_prompts` | `null` | Список описаний классов для CLIP |
| `logging.tensorboard` | `true` | Включение TensorBoard; JSONL остаётся включённым |

Подробности совместимости метрик приведены в разделе 9.

## 7. Практический сценарий: новый эксперимент

Создайте `configs/mnist_custom.yaml`. Например, такой конфиг задаёт другой размер словаря, длину последовательности и архитектуру; пиксельный энкодер не требует дополнительного обучения классификатора:

```yaml
extends: base.yaml

experiment:
  name: mnist_custom
  seed: 42

runtime:
  device: cpu

data:
  ds_name: mnist
  train_limit: 6000
  val_limit: 600
  test_limit: 600

tokenizer:
  decomposition: dct
  ordering: zigzag
  max_tokens: 128
  quantization:
    method: uniform
    num_bins: 256
    per_position: true

model:
  params:
    d_model: 128
    n_heads: 4
    n_layers: 4
    d_ff: 512
    dropout: 0.0

training:
  batch_size: 32
  epochs: 20
  max_steps: 1000
  learning_rate: 0.0003

metrics:
  encoders: [pixels]
  scores: [frechet, precision, recall]
```

После сохранения достаточно проверить конфиг:

```powershell
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_custom.yaml
```

Будущий запуск выполняется заменой подкоманды `validate` на `train`. Изменения исходников для такого варианта существующей модели не нужны.

Для уже подготовленных вариантов можно использовать:

| Конфиг | Особенность |
| --- | --- |
| `configs/mnist_baseline.yaml` | MNIST, первые 64 DCT-коэффициента |
| `configs/mnist_dct_zigzag.yaml` | Полные 784 коэффициента, словарь 256 |
| `configs/mnist_block_dct.yaml` | Блочный DCT, блоки 7×7 |
| `configs/cifar10.yaml` | CIFAR10 RGB, полная последовательность, Inception |
| `configs/smoke.yaml` | Минимальный полный эксперимент; при `train` обучение всё равно выполняется |

Чтобы изменить только устройство или batch size, используйте `--set`. Чтобы сохранить отдельный воспроизводимый вариант, создайте отдельный YAML.

## 8. Как подключать данные

### 8.1. Встроенные наборы

MNIST и CIFAR10 загружаются torchvision при `download: true`. При `false` файлы должны уже присутствовать в `data.root`.

Для CelebA требуется стандартная структура torchvision внутри `<data.root>/celeba/`, включая изображения `img_align_celeba` и файлы разметки. Автоматическое скачивание загрузчиком проекта не выполняется.

Для ImageNet ожидается ImageFolder-структура:

```text
<data.root>/imagenet/
  train/
    class_1/image_001.jpg
    class_2/image_002.jpg
  val/
    class_1/image_101.jpg
    class_2/image_102.jpg
```

Внутренние train/validation выделяются из `train/`; папка `val/` используется как test. Это соглашение текущего загрузчика.

### 8.2. Собственный набор через NPZ без изменения Python-кода

Формат файла:

| Ключ | Требование |
| --- | --- |
| `train_images` | `uint8[N,H,W]` либо `uint8[N,C,H,W]`, C = 1 или 3 |
| `test_images` | Такой же формат; независимый набор для оценки |
| `train_labels` | Необязательный массив целочисленных меток длины N |
| `test_labels` | Необязательный массив меток соответствующей длины |

Диапазон пикселей — 0–255. Формат NHWC нужно заранее преобразовать в NCHW. При отсутствии меток загрузчик подставляет `-1`; авторегрессионное обучение сами метки не использует.

Конфиг собственного набора:

```yaml
extends: base.yaml
experiment:
  name: custom_images
data:
  ds_name: npz
  root: data/custom/images.npz
  gray: true
  size: 28
  download: false
metrics:
  encoders: [pixels]
  scores: [frechet, precision, recall]
```

Для цветного NPZ укажите `gray: false` и продумайте длину токенов; для сохранения всех каналов используйте `tokenizer.max_tokens: null`.

### 8.3. Новый формат загрузки

Если данных нет в поддерживаемых наборах и их нельзя подготовить в NPZ, требуется расширить `src/datasets_loader.py`: добавить имя в `DATASETS` и реализовать загрузку с существующим контрактом `load_images/load_splits`. Результат — изображения NCHW в `[0,1]` и метки.

После реализации загрузчика его выбор выполняется конфигом. Полностью новый формат данных сам по себе не реализуется добавлением строки в YAML.

## 9. Как выбирать и менять метрики

| Энкодер | Особенности | Ограничения |
| --- | --- | --- |
| `pixels` | Downsampling до 8×8; без скачивания весов | Нет вероятностей классов, поэтому `classifier_score` недоступен |
| `mnist` | CNN с 64 признаками и 10 классами | Только `data.ds_name: mnist`; при `train` дополнительно обучается на train |
| `inception` | Предобученный torchvision Inception-v3 | При первом использовании нужны доступные веса или сеть для их загрузки |
| `clip` | CLIP ViT-B/32 | Нужны дополнительные зависимости, веса и непустой `clip_prompts` |

Смена MNIST-метрик на пиксельную диагностику требует заменить оба списка:

```yaml
metrics:
  encoders: [pixels]
  scores: [frechet, precision, recall]
```

Для Inception:

```yaml
metrics:
  encoders: [inception]
  scores: [frechet, classifier_score, precision, recall]
```

Для CLIP список `clip_prompts` должен описывать классы выбранного набора. Текущий валидатор требует его даже тогда, когда запрашиваются только оценки по признакам. Один и тот же список `scores` применяется ко всем выбранным энкодерам: комбинация `pixels` и `classifier_score` недопустима.

### 9.1. Значение оценок

| Оценка | Смысл |
| --- | --- |
| `frechet` | Расстояние между распределениями real/fake признаков; меньше — лучше при неизменном протоколе |
| `classifier_score` | exp(mean KL(p(y\|x) \|\| p(y))); записывается отдельно для fake и real |
| `precision` | Доля fake-признаков внутри kNN-окрестностей real |
| `recall` | Доля real-признаков внутри kNN-окрестностей fake |

`knn_k` должен быть положительным целым и меньше числа real и fake примеров. Для оценок по признакам требуется минимум два примера с каждой стороны.

Число real-примеров для метрик изображений: `min(generation.num_samples, число test-изображений)`. Число fake-примеров: `generation.num_samples`. Test NLL считается на всём выбранном test split, а не только на real-примерах для генеративных метрик.

### 9.2. Правила интерпретации

Fréchet по MNIST CNN, пикселям или CLIP не является стандартным Inception FID. Classifier score имеет смысл Inception Score только при Inception; для других энкодеров это аналогичная формула с другими вероятностями классов.

Даже вариант torchvision Inception не следует напрямую приравнивать результатам специализированных clean-fid/pytorch-fid без согласованной предобработки и весов. Для сравнения экспериментов нужно фиксировать энкодер, число примеров, предобработку, температуру и протокол оценки.

Дополнительно сохраняются NLL, perplexity, token accuracy, bits per token, MSE и PSNR реконструкции токенизатора. Bits per token относится к квантованным коэффициентам, а не к исходным пикселям. NLL при разных токенизаторах напрямую не сравнивают.

Для новой формулы метрики требуется добавить её реализацию, включить в `src/evaluation.py` и обновить допустимые `metrics.scores` в `src/config.py`. Для нового энкодера нужны класс, регистрация в `ENCODERS` и обновление проверки допустимых имён.

## 10. Как подключить другую модель

Изменение ширины, глубины и числа голов существующего Transformer выполняется только через `model.params`.

Для подключения другой уже реализованной архитектуры YAML задаёт Python-пути:

```yaml
model:
  class_path: src.custom_model.CustomModel
  config_class: src.custom_model.CustomConfig
  params:
    hidden_size: 128
    num_layers: 3
```

Это шаблон подключения, а не существующая модель проекта: соответствующие классы нужно предварительно реализовать. При смене `config_class` в наследуемом YAML параметры прежней архитектуры сбрасываются. Для такой смены следует создавать YAML, поскольку поштучное присваивание через CLI не выполняет ту же операцию сброса параметров.

Контракт модели:

1. Класс конфигурации принимает `vocab_size`, `max_seq_len` и свои параметры.
2. Конструктор модели принимает объект конфигурации.
3. Модель наследует `torch.nn.Module` и поддерживает стандартные методы переноса на устройство, режимов и сохранения состояния.
4. `model.config` содержит `vocab_size` и `max_seq_len`; его поля доступны через `vars()` и совместимы с сериализацией checkpoint.
5. `model.bos_token_id` задаёт токен начала последовательности.
6. `forward(tokens)` принимает `torch.long[B,L]` и возвращает логиты `[B,L,V]`.
7. `generate(num_samples, seq_len, device, temperature, top_k)` возвращает `torch.long[B,L]` с токенами в `[0,V-1]`.
8. Предсказание токена не использует будущие токены.

Runner формирует teacher-forcing-входы `[BOS, token_0, ..., token_(L-2)]`, а целью служит исходная последовательность. Во встроенном Transformer BOS имеет ID `vocab_size` и не входит в выходной словарь.

Реализация новой архитектуры требует кода. После соблюдения контракта её подключение к общему запуску выполняется конфигом без переписывания цикла эксперимента.

## 12. Проверки готовности без обучения

Проверка CLI и конфигов:

```powershell
.venv/Scripts/python.exe run_experiment.py --help
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_baseline.yaml
.venv/Scripts/python.exe run_experiment.py validate --config configs/mnist_block_dct.yaml
.venv/Scripts/python.exe run_experiment.py validate --config configs/cifar10.yaml
.venv/Scripts/ruff.exe check .
```

Полный `pytest -q` включает тест с коротким обучением на синтетическом наборе. Чтобы выполнять тесты без обновления весов модели, этот тест нужно исключить:

```powershell
.venv/Scripts/python.exe -m pytest -q -k 'not offline_full_run_and_checkpoint_reevaluation'
```

Оставшиеся тесты могут создавать модель и выполнять forward без градиентов, а также подбирать параметры квантования; оптимизация весов нейросети исключается. Для проверки исключительно конфигов:

```powershell
.venv/Scripts/python.exe -m pytest -q tests/test_config.py
```

Критерии готовности инфраструктуры на данном этапе:

1. Окружение разрешает импорты и не содержит конфликтов установленных зависимостей.
2. Основной CLI доступен; конфиги читаются и разрешаются без обучения.
3. Поддерживаемые варианты выбираются конфигом; ошибки в основных полях выявляются.
4. Форматы данных и контракты модели/метрик описаны.
5. Существуют единые пути запуска, логирования и сохранения состояний.
6. Ограничения валидации и ещё не реализованные возможности явно указаны.

Эти критерии подтверждают готовность инфраструктуры и документации. Они не подменяют будущую проверку полного обучения на выбранных данных и устройстве и не устанавливают порог качества генераций.

## 13. Частые ошибки

| Сообщение или ситуация | Причина и действие |
| --- | --- |
| `Unknown config key` | Опечатка либо попытка добавить новый ключ через `--set`; сверить имя, новые аргументы задать в YAML |
| `Cyclic config inheritance` | Файлы наследуют друг друга по кругу; исправить `extends` |
| `CUDA requested but unavailable` | CUDA недоступна в текущем окружении; выбрать CPU или подготовить CUDA-окружение |
| Каталог запуска уже существует | Повторяется `--run-id`; использовать другое имя либо автоматический ID |
| `max_tokens exceeds image coefficient count` | Длина больше `C×H×W`; уменьшить её или использовать `null` |
| Ошибка разбиения на блоки DCT | Размер блока не делит высоту/ширину; для MNIST 28×28 можно выбрать 7 |
| Ошибка размерностей Transformer/RoPE | Проверить делимость `d_model/n_heads` и чётность размера головы |
| `Pixel encoder has no class probabilities` | Удалить `classifier_score` при использовании `pixels` |
| `MNIST encoder requires the mnist dataset` | Для другого набора выбрать `pixels`, `inception` или `clip` |
| Недопустимый `knn_k` | Сделать k меньше фактического количества real/fake примеров |
| `Dataset contents differ from the saved run` | Изменились данные, порядок или предобработка; восстановить условия исходного запуска |
| Не найдены файлы CelebA/ImageNet | Подготовить данные в ожидаемой структуре; автоматической загрузки этих наборов нет |
| Не хватает RAM/VRAM | Сократить лимиты, batch size, размер изображения, длину или размер модели |

## 14. Ограничения текущей версии

1. `train` запускает полный цикл; отдельных CLI-команд только для токенизации, только для обучения или только для генерации нет.
2. `validate` проверяет основные значения YAML, но не все сочетания аргументов, ресурсы и доступность данных.
3. Автоматическое продолжение прерванного обучения через `resume_from` не реализовано, хотя состояние оптимизатора сохраняется.
4. Все выбранные изображения и токены подготавливаются в оперативной памяти. Потокового обучения на полном ImageNet нет.
5. Нет распределённого обучения, автоматического перебора гиперпараметров, scheduler, mixed precision и gradient accumulation.
6. Генерация идёт без KV-кэша. Длинные RGB-последовательности требуют значительно больше ресурсов.
7. Модель безусловная; управление классом изображения через конфиг генерации не реализовано.
8. MPS предусмотрен выбором устройства, но отдельная проверка совместимости всех операций с ним не следует из проверки YAML.
9. Веса Inception/CLIP могут потребовать загрузки. `data.download: false` не запрещает загрузку весов энкодеров.
10. Seed фиксируется, но побитовая идентичность между разными версиями библиотек и CPU/CUDA/MPS не гарантируется.
11. Для честного сравнения экспериментов необходимо фиксировать протокол оценки; изменение токенизатора меняет пространство токенов и смысл NLL.

Развитие перечисленных возможностей — отдельные задачи. Наличие соответствующих параметров или режимов не следует подразумевать до их реализации.
